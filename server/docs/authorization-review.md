## Audit logging notes

- Every sensitive action is recorded with `recordAudit()` in `src/utils/audit.js`.
- Allowed actions are fixed in `AUDIT_ACTIONS` (for example `consent.granted`, `role.changed`, `access.denied`). A misspelled action is rejected.
- Audit entries are append-only: `save()` on an existing entry, `updateOne`, `updateMany`, `findOneAndUpdate`, `findOneAndReplace`, `replaceOne` and `bulkWrite` updates all throw.
- `meta` may only use keys from `ALLOWED_META_KEYS` (`fromRole`, `toRole`, `reason`, `requestId`, `field`). Every value must be text of at most 200 characters. This stops secrets from being stored in a log that cannot be edited.
- If saving an audit entry fails for a sensitive action (role change, consent change), the action must fail too. For low-risk events, the caller may catch the error and continue.
- Deleting audit entries is not blocked in the model. Only a retention job may delete them, and that job is not built yet.
- Tests: `tests/models/audit.test.js` and `tests/models/childLinked.test.js` (11 tests, run with `npm test`).
