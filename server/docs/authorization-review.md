# Authorization Review (models)

Date: 2026-11-09
Scope: models in `server/src/models`, reviewed against `docs/authorization-matrix.md`.
Not yet reviewed: routes and middleware (they do not exist yet). A second pass is needed once they do.

## Findings

| #   | Model                                                  | Finding                                                                                                                          | Evidence                                                              | Severity | Planned fix                                                                                            | Status |
| --- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------ | ------ |
| F1  | Progress, Assessment, ConsentRecord, TeacherAssignment | `familyId` is stored separately from `childId` and is never checked against the child's real family.                             | Validation hooks only check status and dates; ConsentRecord has none. | High     | Add a validation hook that confirms the child exists, belongs to the family, when a record is created. | Open   |
| F2  | Child                                                  | All fields, including `dateOfBirth`, are returned to every role that can read a child. No limited teacher view is defined.       | `toJSON: { virtuals: true }`, no filtering.                           | Medium   | Define the fields a teacher may see and a helper that returns only those.                              | Open   |
| F3  | ConsentRecord                                          | Updates are ignored silently instead of rejected, and deletes are not guarded. Data cannot change, but the failure is invisible. | All fields `immutable`; no hooks.                                     | Low      | Add explicit guards that throw, and a test that proves updates change nothing.                         | Open   |
| F4  | TeacherAssignment                                      | `isAssigned` ignores suspended teachers and suspended families.                                                                  | Static checks only `status: "active"`.                                | Medium   | Middleware rule: also check user and family status. Documented in the matrix (rule 5).                 | Open   |
| F5  | Child                                                  | No safe lookup that forces the family filter.                                                                                    | No statics defined.                                                   | Medium   | Add a `findOwned(childId, familyId)` helper.                                                           | Open   |
| F6  | Content                                                | The creator can also be the reviewer, so content can approve itself.                                                             | Publish hook does not compare `reviewedBy` and `createdBy`.           | Medium   | Add a validation rule: `reviewedBy` must differ from `createdBy`. Role check goes in the service.      | Open   |
| F7  | AuditEvent                                             | Deletion is not blocked and there is no retention path.                                                                          | No guards for `deleteOne`, `deleteMany`, `findOneAndDelete`.          | Low      | Decide in the audit logging step. Test the `bulkWrite` hook.                                           | Open   |
| F8  | User                                                   | The model cannot prevent a registration request from setting `role`.                                                             | `role` is a normal field with default `parent`.                       | Low      | Controller rule (matrix rule 2). Add a test when the register route exists.                            | Open   |
| F9  | Content                                                | `reviewRequired` can be switched off by the content author, which skips Quran review.                                            | Plain boolean field, default `false`.                                 | Medium   | Ask the PM whether `quran_task` content must always require review. If yes, enforce it in the model.   | Open   |
| F10 | Progress, Assessment                                   | Records can be created for a child whose consent is still pending.                                                               | No check of `Child.status`.                                           | Medium   | Include "child is active" in the F1 validation hook (SEC-001, VAL-008).                                | Open   |
